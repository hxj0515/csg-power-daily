## 2. 交互模型

### 2.1 指针交互（鼠标 / 触屏 / 触控笔统一）

使用 **Pointer Events**，棋盘容器设 `touch-action: none; user-select: none;`。

| 事件 | 行为 |
|---|---|
| `pointerdown` | 命中判定：<br>① 落在某端点 → 清空该色已有路径，开始绘制该色新路径，起点=该端点<br>② 落在某色路径的**任意一格** → 该路径截断到此格，从此格继续绘制<br>③ 落在空格/障碍 → 忽略（不进入拖拽态）<br>命中后 `setPointerCapture` |
| `pointermove` | 由 `clientX/Y` → 棋盘局部坐标 → 格子索引。仅当目标格与当前线尾**正交相邻**时才推进一格；若指针一次移动跨越多格（快速拖动），沿**曼哈顿路径逐格补插**（先走行再走列，且每格都需通过合法性检查，任一格非法则停在最后合法格） |
| 推进合法性 | 目标格为空 → 占用并推进；<br>目标格是本色路径的**上一格** → 回撤一格；<br>目标格是本色路径的**中段** → 截断到该格；<br>目标格是本色的**另一端点** → 连接完成，结束本次拖拽（自动 `pointerup` 语义）；<br>目标格是**他色路径** → 他色从被撞格起截断至尾部，本色占用该格；<br>目标格是**他色端点**或障碍 → 拒绝，线尾不动 |
| `pointerup` / `pointercancel` | 结束拖拽。**保留未完成的半截路径**（不回滚）——降低挫败感。记 1 步 |
| 长按端点（≥450ms 未移动） | 清空该颜色整条路径 + 轻震动反馈 |
| 右键 / 双指点击 端点 | 同长按（桌面端快捷方式），需 `preventDefault` 屏蔽右键菜单 |

**手感参数（可调常量）**
```js
const TOUCH = {
  hitRadiusRatio: 0.62,   // 命中半径 = 格边长 × 该值，宽容命中
  longPressMs: 450,
  minCellPx: 34,          // 格子最小像素，低于此值则缩小网格显示区
  fingerOffsetPx: 0       // 触屏可设 -18 让线尾在手指上方（默认 0，A/B 后定）
};
```

**移动端专项**
- 竖屏优先布局：棋盘居中占宽度 92%，最大 `min(92vw, 62vh)`。
- 棋盘上方留 ≥56px 顶栏，下方 ≥64px 底栏，避免手指遮挡与浏览器手势冲突。
- 阻止双击缩放：`<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no">`。
- iOS 橡皮筋：`body { overscroll-behavior: none; }`。

### 2.2 键盘交互（可访问性必备）

| 按键 | 行为 |
|---|---|
| `Tab` / `Shift+Tab` | 在 UI 控件间移动焦点（棋盘作为单一可聚焦元素 `tabindex="0"`） |
| 棋盘聚焦后 `↑↓←→` | 移动虚拟光标（高亮方框） |
| `Enter` / `Space` | 在端点上按下 = 拾起该色；再次按下 = 放下；拾起状态下方向键即为画线 |
| `Backspace` | 回撤一格 |
| `Z` | 撤销一步 |
| `R` | 重置本关 |
| `H` | 提示 |
| `Esc` | 打开/关闭暂停浮层 |

### 2.3 反馈规范

| 时机 | 视觉 | 听觉（WebAudio 合成） | 触觉 |
|---|---|---|---|
| 拖拽推进一格 | 线条延伸 | 无（避免噪音） | 无 |
| 一对连通 | 线路通电流光 ≤200ms + 两端点脉冲 | 「合闸」短促上行三音 | `navigator.vibrate(12)` |
| 抢占截断他色 | 被截断段快速淡出 120ms | 极轻的 click | 无 |
| 全部连通 | 全盘流光 → 结算页城市点亮 | 上行五音 | `vibrate([20,40,20])` |
| 非法操作 | 线尾轻微抖动 80ms | 无 | 无 |

> 全部动效必须在 `prefers-reduced-motion: reduce` 或设置中「降低动效」开启时退化为**瞬时切换**（时长置 0），且不得影响任何游戏逻辑。

## 3. 存档规格（多档案）

### 3.1 localStorage 键

| 键名 | 内容 | 说明 |
|---|---|---|
| `powerlink:profiles:v1` | `Profile[]` 的 JSON 字符串 | 全部档案，上限 6 |
| `powerlink:current:v1` | `string`（档案 id，裸字符串不加引号也可，建议存 JSON 字符串） | 当前档案 id；若指向不存在的 id 则回落到数组第 0 个 |
| `powerlink:app:v1` | `{ schema:1, lastOpenedAt }` | 应用级元信息（非档案数据），可选 |

> 键名前缀统一 `powerlink:`，避免与根目录日报页面（同源 `hxj0515.github.io`）的任何存储冲突。**严禁使用无前缀的通用键名**，这是与根仪表盘共享 origin 的硬性要求。

### 3.2 Profile 对象结构

```jsonc
{
  "id": "p_l3k9x2a7",            // string, 生成: 'p_' + Date.now().toString(36) + rand4
  "name": "调度员小林",            // string, 1–8 字符（截断），HTML 转义后渲染
  "color": "#38e1ff",            // string, 取自头像色板 6 色
  "icon": "bulb",                // 'plant'|'bulb'|'battery'|'tower'|'plug'|'bolt'
  "createdAt": 1754800000000,    // number, epoch ms
  "updatedAt": 1754899999000,    // number, epoch ms，每次写盘刷新

  "levels": {                    // 闯关进度，key = levelId，如 "p1-07"
    "p1-01": { "stars": 3, "bestMoves": 9, "completed": true },
    "p1-02": { "stars": 1, "bestMoves": 22, "completed": true },
    "p2-03": { "stars": 0, "bestMoves": 0, "completed": false }  // 仅"玩过未通"时才写
  },

  "daily": {                     // 每日挑战，key = 本地日期 "YYYY-MM-DD"
    "2026-08-10": { "stars": 3, "bestMoves": 14, "completed": true }
  },

  "dailyStreak": {               // 连胜统计（派生但缓存，避免遍历）
    "current": 5,
    "best": 12,
    "lastDate": "2026-08-10"
  },

  "inProgress": {                // 断点续玩（最多保存 1 局），无则为 null
    "mode": "level",             // 'level' | 'daily'
    "levelId": "p3-08",          // daily 模式时为日期字符串
    "moves": 7,
    "usedHint": false,
    "startedAt": 1754899000000,
    "paths": {                   // key = 颜色索引(字符串), value = 格子序列 [r,c][]
      "0": [[0,0],[0,1],[1,1]],
      "2": [[4,4],[4,3]]
    }
  },

  "settings": {
    "sound": true,
    "vibrate": true,
    "shapes": true,              // 色盲形状标记
    "reduceMotion": false        // false = 跟随系统
  },

  "stats": {                     // 可选但建议，成本极低
    "totalMoves": 1420,
    "totalPlayMs": 3600000,
    "levelsCompleted": 37,
    "perfectCount": 21
  }
}
```

**字段变更说明（相对主理人初稿）**：新增 `inProgress`（断点续玩，直接支撑"摸鱼随时中断"的核心场景）、`dailyStreak`（避免每次遍历 daily 对象）、`stats`、`settings.vibrate/shapes/reduceMotion`。其余键名与初稿完全一致，**向后兼容**。

### 3.3 读写规则

```js
// 读取：任何一步失败都返回安全默认值，绝不抛错到调用方
function loadProfiles() {
  try {
    const raw = storage.getItem('powerlink:profiles:v1');
    if (!raw) return [];
    const arr = JSON.parse(raw);
    if (!Array.isArray(arr)) return [];
    return arr.map(migrateProfile).filter(Boolean);   // 逐个校验+补默认字段
  } catch (e) { console.warn('[powerlink] 读档失败，已重置为空', e); return []; }
}
```

- `migrateProfile(p)`：校验 `id`/`name` 为字符串，缺失的对象字段补 `{}`，缺失的 `settings` 补默认；任何单个档案损坏则丢弃该档案而不是整体清空。
- **写盘失败降级**：`setItem` 抛错（隐私模式 / 配额满 / `file://` 不透明源）→ 切换到内存 `Map` 存储，并在顶部显示常驻提示条：「当前浏览器环境无法保存进度，本次成绩不会被记录」，同时把「导出存档」按钮高亮。
- **存储探测**：启动时执行一次 `storage.setItem('powerlink:probe','1'); storage.removeItem('powerlink:probe')` 的 try/catch 探测，结果缓存。
- **单档案体积估算**：180 关 + 365 天 daily ≈ 45KB JSON，6 档案 ≈ 270KB，远低于 5MB 配额，安全。

### 3.4 自动保存时机

| 时机 | 保存内容 | 方式 |
|---|---|---|
| 关卡通关（结算前） | `levels[id]` / `daily[date]` + `stats` + 清空 `inProgress` | 立即同步写 |
| 每日挑战通关 | 同上 + 更新 `dailyStreak` | 立即写 |
| 游戏中每完成一步 | `inProgress` | **防抖 400ms** 写 |
| 退出游戏屏 / 打开暂停浮层 | `inProgress` | 立即写 |
| 设置项变更 | `settings` | 立即写 |
| 档案增删改 / 切换 | `profiles` + `current` | 立即写 |
| `visibilitychange → hidden`、`pagehide` | 全量 flush（取消防抖直接写） | 立即写 |
| 「跳过本关」 | 清空 `inProgress`，不写 `levels` | 立即写 |

> 每次写盘统一经过 `saveProfiles()`，内部自动刷新当前档案的 `updatedAt`。

### 3.5 导出 / 导入 JSON

**导出格式**
```jsonc
{
  "version": 1,
  "app": "powerlink",
  "exportedAt": 1754899999000,
  "profiles": [ /* Profile[] 原样 */ ]
}
```
- 文件名：`powerlink-save-YYYYMMDD-HHmm.json`
- 实现方式（无外部依赖）：`new Blob([json], {type:'application/json'})` + `URL.createObjectURL` + 临时 `<a download>` 点击。
- **`file://` 兜底**：若下载被拦截，弹出一个只读 `<textarea>` 展示 JSON 全文 + 「复制到剪贴板」按钮（`navigator.clipboard` 失败则 `document.execCommand('copy')`）。

**导入规则**
1. 入口：`<input type="file" accept=".json,application/json">`，**并额外提供「粘贴 JSON 文本」输入框**（`file://` 与移动端更可靠）。
2. 解析：`try { JSON.parse } catch → 提示「文件不是合法的 JSON」并中止`。
3. 校验：`data.version === 1`（未来版本走迁移表，未知版本提示不兼容）；`Array.isArray(data.profiles)`。
4. **合并策略（按 id）**：
   - 同 id 存在 → **覆盖**本地档案（与主理人初稿一致）。但在覆盖前弹确认框列出将被覆盖的档案名。
   - 新 id → 追加。
   - 追加后若总数 > 6 → 提示「最多 6 个档案，请先删除部分档案」并中止整次导入（**全或无**，不做半途导入）。
   - 每个导入档案单独跑 `migrateProfile`，损坏的跳过并计入报告。
5. 结果反馈：`已导入 2 个档案（覆盖 1 个，新增 1 个），跳过 0 个损坏项`。
6. 导入后不自动切换当前档案，除非当前档案 id 已不存在。
7. 整个流程包在 try/catch 中，任何异常都只提示不崩溃，**且失败时不得写入 localStorage**（先在内存构造出完整新数组，成功后一次性写盘）。

## 4. 断点续玩

- 进入 S5 时若 `inProgress` 存在且 `levelId` 匹配当前关 → 直接恢复 `paths` 与 `moves`。
- 若 `inProgress` 存在但玩家选了**别的**关 → 弹确认：「你还有一局『区域主网 08』没打完，是否放弃？」（放弃 / 先回去继续）。
- `inProgress.mode === 'daily'` 且 `levelId !== 今日日期` → 静默丢弃（昨天的没打完不保留）。

## 5. 星级评定规则

**定义**
```
可用格数 usable = 总格数 − 障碍格数            (MVP 无障碍格，usable = N×N)
已占格数 filled = 所有路径经过的格数 + 所有端点格数（端点计入其所属路径，不重复计）
覆盖率 coverage = filled / usable              (0 ~ 1)
```

| 星级 | 条件 |
|---|---|
| 0★ | 未全部连通（未通关） |
| **1★** | 所有颜色对连通 |
| **2★** | 所有颜色对连通 **且** `coverage ≥ 0.80` |
| **3★** | 所有颜色对连通 **且** `coverage === 1.0`（满铺，逐格判定，不用浮点比较） |

**附加规则**
- 本局使用过提示（`usedHint === true`）→ 本局结算星级 **上限 2★**（重玩不用提示可拿回 3★）。
- 星级 **只增不减**：`stars = Math.max(old.stars, new.stars)`。
- `bestMoves` **只减不增**：仅在本局通关时更新 `bestMoves = old ? Math.min(old, moves) : moves`。
- 覆盖率判定必须用整数计数（`filledCount === usableCount`），**禁止用 `coverage === 1` 的浮点判断**。
- 2★ 同样走整数比较：`filled * 100 >= total * STAR2_COVER_PERCENT`（**整数乘法，不做除法**），避免 `0.8` 在浮点下的边界抖动。
- 结算页需显示 `18/25 格（72%）`，让 2★→3★ 的差距可量化、可行动。

**设计说明**：因为关卡生成保证存在 100% 满铺解（见 concept.md §7.2），3★ 恒可达；1★ 门槛极低保证胜任感，2★/3★ 提供精进空间。这套规则**不引入步数门槛**，避免"背最优解"式的主导策略与挫败感。

## 6. 每日挑战：种子生成思路

### 6.1 日期与种子

```js
// 本地日期字符串，避免 UTC 造成的"跨零点错题"
function todayStr(d = new Date()) {
  const p = n => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${p(d.getMonth() + 1)}-${p(d.getDate())}`;
}

// xmur3 字符串哈希 → 32bit 种子
function xmur3(str) {
  let h = 1779033703 ^ str.length;
  for (let i = 0; i < str.length; i++) {
    h = Math.imul(h ^ str.charCodeAt(i), 3432918353);
    h = (h << 13) | (h >>> 19);
  }
  return () => {
    h = Math.imul(h ^ (h >>> 16), 2246822507);
    h = Math.imul(h ^ (h >>> 13), 3266489909);
    return (h ^= h >>> 16) >>> 0;
  };
}

// mulberry32 确定性 PRNG
function mulberry32(a) {
  return () => {
    a |= 0; a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

const seedFn = xmur3('powerlink-daily-' + todayStr());
const rng = mulberry32(seedFn());
```

**要点**
- 种子只依赖日期字符串，**不依赖档案 id** → 同一天所有玩家、所有档案得到**完全相同**的题目（这是"办公室话题"社交价值的来源）。
- 全流程只用 `rng()`，**严禁在生成器里调用 `Math.random()`**（哪怕一次也会破坏确定性）。
- 时区说明：使用**设备本地日期**。同一天不同时区的玩家可能拿到不同题（如东八区已是 11 号、UTC 还是 10 号）。这是可接受的取舍——本作用户高度集中在 UTC+8，且不做联网比对。**需在「关于」页注明"每日挑战按你设备的本地日期生成"**。

### 6.2 难度轮换（实现口径）

难度由**种子本身**抽取，而非按星期查表。抽取分布如下（对应 `levels.js` 的 `PowerLinkDaily()`）：

| 维度 | 取值池 | 说明 |
|---|---|---|
| 网格 `size` | `[6,6,6, 7,7,7, 8,8, 9]` | 6×6 与 7×7 各占 1/3，8×8 占 2/9，9×9 占 1/9（偶尔的硬题） |
| 对数 `K` | 6×6 → 4–6 ／ 7×7 → 5–7 ／ 8×8·9×9 → 5–7 | 随尺寸浮动 |
| 方差 `σ` | `[low, mid, mid, high, high]` | 中高方差为主，保证每日题有嚼头 |

> **设计说明（与原稿的差异）**：初稿设想的是"周一最易 → 周日最难"的**星期节律表**。实现改为种子随机抽取，代价是失去了一周内的固定起伏感，收益是题目类型更不可预测、避免玩家形成"周一随便打"的惰性预期。
> 两种方案对核心体验影响都不大，**设计组接受当前实现**。若后续用户反馈"每日难度忽高忽低很烦"，可低成本改回星期查表（只需把 `sizeTable/sigmaTable` 的抽取换成 `new Date(dateStr).getDay()` 查表，不影响确定性）。

### 6.3 生成流程（复用 concept.md §7.2 算法）

```
'powerlink|daily|YYYY-MM-DD' → xfnv1a 哈希 → mulberry32 rng
  → 蛇形哈密顿路径 + rng 驱动的 backbite 扰动（保哈密顿性，永不失败）
  → 按 K 与 σ 长度带切段（切点由 rng 选取）
  → 合法性过滤（段长≥3、端点不相邻、单段≤55%）
  → 不通过则用 rng 继续扰动重切
  → 兜底：回落到"纯蛇形均分切段"（必定合法，确保永远有题）
  → 输出 { size, pairs:[{color,shape,label,endpoints,solution}], ... }
```

- 生成必须是**纯函数**：`PowerLinkDaily(dateStr) → 同样输入永远同样输出`。工程需写一个自测：同一日期连跑 100 次结果 JSON 完全一致。
- **确定性依赖 32 位整数运算**（`Math.imul` + 无符号位移），保证跨 JS 引擎位级一致；生成器内严禁 `Math.random()`。
- 生成耗时目标 **<30ms**（8×8 规模）。实现已带 `DAILY_CACHE` 按日期缓存，同一天只算一次。
- 生成结果**不必写入 localStorage**（随时可重算），只把成绩写入 `daily[dateStr]`。
- 入参需容错：非 `YYYY-MM-DD` 格式一律回落到今天（实现已做正则校验）。

### 6.4 每日挑战 UI 规则

- 当天已完成 → 按钮变「重玩今日」，成绩仍按"星级只增不减"更新。
- 提供「最近 7 天」小方格：满铺=实心青、通关=描边青、未玩=灰。**不允许补做往日题目**（保持仪式感，也避免刷连胜）。
- `dailyStreak.current`：若 `todayStr` 与 `lastDate` 相差 1 天则 +1，相差 >1 天则重置为 1；同日重复完成不累加。

## 7. 可访问性规格

### 7.1 色觉无障碍（硬性要求）

- **每种线缆颜色绑定一个唯一形状**，形状绘制在**两个端点**内部（详见 `art-direction.md` §2）。形状是默认开启的，不是可选装饰。
- 已完成连通的线路，其**路径中点**额外绘制一次小尺寸形状标记（长路径每隔 4 格重复一次），保证在只看线不看端点时也能分辨。
- 设置中「形状标记」可关（给不需要的玩家更干净的画面），但**默认开启**。
- 相邻颜色索引之间保证 **CIE ΔE > 25** 且**明度差 > 15**，颜色分配按预排序表从索引 0 依次取用。
- 选中/激活状态不能只靠颜色变化，必须叠加**加粗描边 + 发光**。

### 7.2 其它

| 项 | 要求 |
|---|---|
| 触控目标 | 所有可点击 UI ≥ **44×44 CSS px**；棋盘格最小 34px，命中半径放宽到 0.62 格 |
| 文字对比度 | 正文文字对背景 ≥ **4.5:1**；大字号标题 ≥ 3:1。`#e6f0ff` on `#0b1020` ≈ 15:1 ✓；辅助文字最暗不得低于 `#8ea3c8` |
| 字号 | 正文最小 **14px**，说明性小字最小 12px 且不承载关键信息 |
| 键盘 | 全流程可键盘操作（见 §2.2）；所有可聚焦元素有清晰 `:focus-visible` 轮廓（2px 电光青 + 2px 外发光） |
| 屏幕阅读器 | 关键状态用 `aria-live="polite"` 播报：「第 3 对已接通，还剩 2 对」「通关，3 星，覆盖率 100%」；棋盘 canvas 提供 `aria-label` 概述 + 隐藏的 DOM 文本镜像（每行一段"第1行：发电站(圆) 空 空 …"） |
| 动效 | 尊重 `prefers-reduced-motion`；设置中可强制关闭。关闭后无任何位移/缩放/闪烁动画 |
| 闪烁 | 任何动效频率 **< 3Hz**，禁止全屏高对比闪烁（光敏性癫痫风险） |
| 语言 | `<html lang="zh-CN">` |
| 缩放 | 页面在 200% 浏览器缩放下仍可用（布局用相对单位，棋盘用 `min(vw, vh)` 约束） |

## 8. 错误与边缘情况清单（工程必须覆盖）

| # | 场景 | 期望行为 |
|---|---|---|
| E1 | `localStorage` 完全不可用（`file://` 隐私模式） | 降级内存存储 + 常驻提示条 + 高亮导出按钮，游戏功能完全正常 |
| E2 | `profiles` 键内容被外部改坏（非 JSON / 非数组） | 捕获异常，视为空档案列表，引导创建新档案，**不清除原始坏数据**（保留以便人工救援），改用 `powerlink:profiles:v1` 覆写前先备份到 `powerlink:profiles:backup` |
| E3 | `current` 指向已删除的档案 id | 回落到 `profiles[0]`；若数组为空 → 进 S1 创建流程 |
| E4 | 导入的 JSON 里 `profiles` 含 20 个档案 | 超过上限 → 整次导入中止并提示，不做部分导入 |
| E5 | 导入文件 version ≠ 1 | 提示「存档版本不兼容（v{n}）」并中止 |
| E6 | 两个浏览器标签页同时打开游戏 | 监听 `storage` 事件；检测到外部写入时提示「另一个标签页修改了存档，已重新载入」并刷新内存状态（避免互相覆盖） |
| E7 | 拖拽中指针移出窗口 / 切到后台 | `pointercancel` + `visibilitychange` 均视为 `pointerup`，保留半截路径并写盘 |
| E8 | 快速拖拽跨越多格 | 曼哈顿逐格补插，遇非法格即停，**绝不允许出现"跳格连线"** |
| E9 | 窗口 resize / 手机旋屏 | 重算格边长与 canvas 尺寸（含 DPR），**路径数据以格子索引存储，与像素无关**，重绘即可，不丢进度 |
| E10 | 系统日期被回调到过去 | `dailyStreak` 计算差值为负 → 视为断连，重置 `current = 1`，不做惩罚 |
| E11 | 同一档案名重复 | 允许（用 id 区分），但档案卡上显示创建时间以便辨认 |
| E12 | 玩家在结算动画播放中疯狂点击 | 结算期间禁用输入 300ms，动画可点击跳过直接到终态 |
| E13 | 关卡数据里某关损坏（pairs 缺失） | 关卡选择页该关标记为「数据异常」不可点，不影响其它关 |
| E14 | 用户昵称输入 `<script>` | 全部用 `textContent` 渲染，**禁止 `innerHTML` 拼接用户输入** |
| E15 | 每日挑战跨零点（玩到一半到了第二天） | 以**进入关卡时**的日期为准结算，不中途换题；结算后刷新页面才拿到新题 |
