## 0. 一句话定位

**在电网调度盘上一笔一笔把发电站接到用电点，铺满全城不断电。**
Flow-Free 式点线连接解谜 + 电力能源主题皮肤 + 闯关三星 + 每日挑战 + 多人本地存档。

## 1. 设计支柱（3 条）

所有后续设计决策必须能追溯到这 3 条中的至少一条；违背任意一条的功能一律砍掉。

| # | 支柱 | 含义 | 落地约束（可验收） |
|---|---|---|---|
| **P1** | **零门槛：看一眼就会玩** | 不需要文字教程，规则从画面自明。同色端点 = 要连；线不能交叉 = 显而易见 | 首关 5×5、3 对端点、必有一条"傻瓜解"；首次进入只用 1 句浮层提示 + 1 个手指动画；**不做多页教学** |
| **P2** | **推理优先，而非试错碾压** | 每关存在一个可被"看出来"的关键洞察（角落必走、边缘唯一通道），而不是靠反复乱拖撞出来 | 关卡生成/校验必须保证**存在 100% 满铺解**；不出现需要 20 步以上盲试才能推进的关；撤销/重画**零惩罚、零消耗** |
| **P3** | **点亮的即时快感** | 电力主题不是贴图，是反馈：接通瞬间线路通电流光，全部接通时城市灯光亮起 | 每次配对成功有 ≤200ms 的通电光效 + 音效；结算页有"城市点亮"动画；无失败态、无倒计时、无生命值 |

**支柱漂移红线**：若后续有人提出"加体力值/加广告解锁/加限时倒计时"，直接违背 P3（休闲消遣定位），需回主理人复议。

## 2. MDA 框架分析

### 2.1 Mechanics（机制层 · 引擎要实现的规则）

**MVP 机制集（必须实现）**

| 机制 | 规则定义 |
|---|---|
| 网格 | `W × H` 正交网格，MVP 只用正方形 `N × N`，N ∈ {5,6,7,8,9} |
| 端点对 | 每种颜色恰好 2 个端点（发电站 / 用电点），端点占据格子且不可被别的线穿过 |
| 画线 | 从端点或自身线尾出发，沿**四邻域**逐格延伸；不可斜走 |
| 占用互斥 | 一格最多属于一条线路 |
| 覆盖抢占 | 拖入他色已占格 → 该色路径从被撞点起**截断到尾部**（标准 Flow 行为），不弹错误提示 |
| 自我回撤 | 拖回自身路径的上一格 → 回退一格；拖到自身路径中段 → 截断到该点 |
| 完成配对 | 线尾抵达同色另一端点 → 该对锁定为"已通电"（仍可重画） |
| 清除单色 | 长按/右键端点 → 清空该色路径 |
| 撤销 / 重置 | Undo 栈（≥50 步）+ 一键重置全盘 |
| 计步 | 一次完整的 pointerdown→pointerup 拖拽 = 1 步（用于个人最佳记录，**不影响星级**） |
| 胜利判定 | 所有颜色对均已连通 → 胜利 |
| 覆盖率 | `已被线路/端点占用格数 ÷ (总格数 − 障碍格数)` → 决定星级 |

**完整版扩展机制（MVP 不做，按需分批开）**

| 机制 | 规则 | 引入目的 |
|---|---|---|
| 检修区（障碍格） | 永久不可通行的格子 | 打破对称，制造唯一通道 |
| 变电站（中继格） | 指定颜色的线路**必须**穿过该格 | 增加约束推理 |
| 立交桥（跨接格） | 两条线可在此格垂直交叉（各走直线） | 拓扑难度跃升 |
| 限步模式 | 给定步数上限的额外模式（独立入口，不污染主线） | 技巧向玩家的深水区 |
| 双端发电站 | 一个发电站带 2 个用电点（三端连通） | 后期变体 |

### 2.2 Dynamics（动态层 · 玩家实际会涌现的行为）

- **边角优先启发式**：老手会先解角落和贴边端点（自由度最低），这是我们希望涌现的"技巧感"来源。
- **覆盖率博弈**：玩家先"连通"拿 1★，再回头改路线追求满铺 3★ —— 这是主循环之外的**自发二周目**，是留存关键。
- **抢占重连节律**：因为覆盖抢占无惩罚，玩家会形成"大胆试 → 被截断 → 立刻修"的高频微循环，节奏约 2–5 秒一次，制造"手不停"的消遣感。
- **每日仪式**：每日挑战全服同题（同种子），形成"今天这题好难/我 3★ 了"的办公室话题 —— 弥补单机无社交的短板。
- **档案共用**：一台办公电脑多人各自建档，形成低成本的**同事间比较**。

**需要警惕的负面动态（红线）**

| 风险 | 说明 | 对策 |
|---|---|---|
| **主导策略** | 若允许"蛇形一笔画填满整盘"永远成立，玩家会用固定套路秒杀所有关 | 生成器必须保证多对端点**分布离散**（不允许一条路径覆盖 >55% 格子），且路径长度方差受控 |
| **认知过载** | 9×9 + 8 对颜色同屏，色盲/中年用户会崩 | 单关颜色数上限 **7**；≥8×8 时强制启用形状标记；颜色按感知距离排序表取用 |
| **枯燥同质** | 60 关全是同一种感觉 | 每个关卡包换网格尺寸 + 端点密度，锯齿式难度（见 §7） |

### 2.3 Aesthetics（美学层 · 玩家追求的乐趣类型）

按 MDA 八类美学，本作**主打 2 类、辅助 2 类**：

| 优先级 | 美学类型 | 在本作中的体现 |
|---|---|---|
| ★主 | **Challenge（挑战）** | 三星覆盖率目标、限步模式、每日挑战 |
| ★主 | **Sensation（感官）** | 通电流光、城市点亮、清脆的合闸音效、拖线的顺滑手感 |
| ○辅 | **Submission（消遣）** | 无失败、无计时、随时退出自动保存 —— 摸鱼 90 秒即可完成一关 |
| ○辅 | **Discovery（发现）** | 新关卡包解锁新机制（障碍→中继→立交），"原来还能这样" |

**明确不追求**：Fantasy（叙事沉浸）、Narrative（剧情）、Fellowship（多人社交）。不要写剧情文案，主题氛围靠视觉与命名承载即可。

## 3. 玩家心理设计（自我决定论 SDT + 心流）

### 3.1 自我决定论三需求

| 需求 | 设计手段 | 验收点 |
|---|---|---|
| **自主 Autonomy** | ① 关卡选择自由，**不强制线性通关**（同包内任意关可点）② 卡关可跳过，跳过不惩罚 ③ 提示按钮完全可选、无冷却、无货币 ④ 档案可自定义名字/头像色/图标 ⑤ 音效可关 | 任一时刻玩家至少有 3 个可选去处 |
| **胜任 Competence** | ① 1★ 门槛极低（连通即得），保证"必定成功"② 2★/3★ 提供可选精进目标 ③ 撤销零惩罚，消除操作恐惧 ④ 关卡包内难度渐进，网格尺寸缓慢上升 ⑤ 显示个人最佳步数（自己跟自己比） | 新手前 5 关**通关率应 ≥95%** |
| **关联 Relatedness** | ① 多档案（家人/同事共用一台设备）② 每日挑战全员同题 ③ 存档导出 JSON 可发给同事导入对比 ④ 主题贴合"南方电网"同事群体的职业认同 | 档案切换 ≤2 次点击 |

### 3.2 心流难度曲线

采用**锯齿型（Sawtooth）节律**而非单调上升：每 4 关中 3 难 1 缓，避免持续紧张导致弃玩。

```
难度
 ↑
 │                                   ╱▔╲    ← 包末 boss 关
 │                      ╱▔╲   ╱▔╲  ╱    ╲
 │        ╱▔╲   ╱▔╲   ╱    ╲╱   ╲╱      ╲_ ← 缓冲关（放松，拿 3★ 很轻松）
 │  ╱▔╲ ╱    ╲╱    ╲╱
 │ ╱   ╲
 └──────────────────────────────────────────→ 关卡序号
   L1                                    L15
```

- **技能带**：玩家技能提升主要来自"边角优先"和"路径长度直觉"，我们通过网格尺寸和端点密度控制难度带宽。
- **焦虑侧防护**：任一关连续失败/重置 **≥5 次**或停留 **≥180 秒** → 主动弹出「要看个提示吗？」（可永久关闭该提醒）。
- **无聊侧防护**：单关若被玩家 **<15 秒** 3★ 通过，则同包后续关自动不再出同尺寸的低密度关（MVP 可简化为：静态曲线已保证密度递增）。

## 6. 核心循环与进度系统

### 6.1 核心循环（微观，20–120 秒/次）

```
   ┌──────────────────────────────────────────────────┐
   │                                                  │
   ▼                                                  │
 选关 ──► 观察端点分布 ──► 拖线连接 ──► 冲突/截断 ──► 修正
                              │                       │
                              └──► 全部连通 ──► 计算覆盖率
                                                  │
                                          ┌───────┴────────┐
                                          ▼                ▼
                                    满铺 3★ 结算      未满铺 1–2★
                                          │                │
                                          │          「再试一次追 3★」◄┘
                                          ▼
                                    城市点亮动画 ──► 下一关 ─────────┘
```

### 6.2 元循环（宏观，跨会话）

```
完成关卡 → 获得星星 → 累计总星 → 解锁新关卡包 → 遇到更大网格/新机制
      ↘                                                      ↙
        每日挑战（每天 1 题）→ 连续天数 → 档案里的"连胜"徽标
```

### 6.3 胜负与进度规则

| 项 | 规则 |
|---|---|
| **失败条件** | **无**。不存在失败态。玩家只能"未完成"，随时可退出并保留进度 |
| **胜利条件** | 所有颜色对连通 |
| **星级** | 1★ 连通 ／ 2★ 连通且覆盖率 ≥80% ／ 3★ 连通且覆盖率 100%（详见 ux-save-spec.md §5） |
| **星级只增不减** | 重玩同关只更新更高星级与更低步数，不会掉星 |
| **关卡解锁** | 同包内**全部关卡默认可玩**（自主性优先），不做逐关解锁 |
| **关卡包解锁** | 包 1 默认开放；包 N+1 需累计 **该包前置总星数的 50%**（见下表），门槛刻意宽松 |
| **跳过** | 关卡内可"跳过本关"，不给星，不影响解锁 |

| 关卡包 | id | 名称 | 网格 | 关数 | 满星 | 解锁条件 |
|---|---|---|---|---|---|---|
| Pack 1 | `p1` | 配电小区 | 5×5 → 6×6 | 15 | 45★ | 默认开放 |
| Pack 2 | `p2` | 城区变电 | 6×6 → 7×7 | 15 | 45★ | 累计 ≥22★ |
| Pack 3 | `p3` | 区域主网 | 7×7 → 8×8 | 15 | 45★ | 累计 ≥50★ |
| Pack 4 | `p4` | 特高压枢纽 | 8×8 → 9×9 | 15 | 45★ | 累计 ≥80★ |
| — | — | 每日挑战 | 6×6~9×9 轮换 | 每日 1 | — | 默认开放 |

> **包内跨尺寸**：每个包**内部**从小网格过渡到大网格（如 Pack 1 前 9 关 5×5、后 6 关 6×6），下一包的起始尺寸 = 上一包的结束尺寸。这样尺寸提升发生在包**内**而非包**间**，玩家不会在跨包时遭遇断崖，是比"一包一个固定尺寸"更平滑的爬升。

> 总星 180★。以"平均每关 2★"计算，玩家在 Pack1 结束时约有 30★，可直接进 Pack2；不会卡关，符合 P3 休闲定位。

## 7. 难度曲线设计（关卡参数表）

难度由 4 个旋钮控制：**网格边长 N**、**端点对数 K**、**平均路径长度 L̄ = N²/K**、**路径长度方差 σ**。

- `K` 越大 → 每条路径越短 → 但可选组合爆炸，**中等 K 最难**（K ≈ N×0.7 时约束最松、试错空间最大）。
- `σ` 越大（有的线很长有的很短）→ 越难，因为玩家难以判断哪条该绕远路。

### 7.1 逐包参数

| 包 | 关 1–4（导入） | 关 5–8（成长） | 关 9–12（挑战） | 关 13–15（收尾/Boss） |
|---|---|---|---|---|
| **Pack 1** 5×5→6×6 | K=3, σ 低 | K=4, σ 低 | K=4, σ 中 | 升 6×6, K=5, σ 中 |
| **Pack 2** 6×6→7×7 | K=4, σ 低 | K=5, σ 中 | K=5, σ 高 | 升 7×7, K=6, σ 高 |
| **Pack 3** 7×7→8×8 | K=5, σ 中 | K=5, σ 高 | K=6, σ 高 | 升 8×8, K=7, σ 高 |
| **Pack 4** 8×8→9×9 | K=5, σ 中 | K=6, σ 高 | K=7, σ 高 | 升 9×9, K=7, σ 高 |

**锯齿节律**：每包的第 4、8、12 关刻意设为"缓冲关"（σ 低、K 比相邻关少 1），给玩家一个轻松 3★ 的呼吸点。

**σ 档位的实现口径**（与 `levels.js` 的 `lengthBand()` 对齐）：σ 控制单段路径长度相对均值 `avg = N²/K` 的浮动区间——
`low` = [0.78×avg, 1.32×avg]（长度整齐，易读）｜`mid` = [0.58, 1.66]｜`high` = [0.38, 2.10]（长短悬殊，需判断哪条该绕远路）。

> 权威数据源为 `levels.js` 的 `LEVEL_PLAN` 数组（每行 `[名称, 包, 尺寸, K, σ]`），本表为设计意图说明。两者若冲突以 `LEVEL_PLAN` 为准，并回头同步本表。

### 7.2 关卡数据生成方式（给工程的实现建议）

为满足 P2（必存在 100% 满铺解），采用**"先造解、再挖题"**的构造式生成，而非随机布点后求解：

1. 在 N×N 网格上生成一条**哈密顿路径**（经过所有格子恰好一次）：以**蛇形路径**起手（任意 N×N 必然存在），再用 **backbite 变换**随机扰动。
2. 按目标 K 与 σ 档位，把这条路径**切成 K 段连续子路径**。
3. 每段的两个端点即为一对同色端点 → 天然保证"所有格子被覆盖"的解存在。
4. 合法性过滤：
   - 每段长度 ≥3（避免相邻两格直接成对的白给关）；
   - 一对端点不得正交相邻；
   - 单段长度 ≤ 总格数 × 55%（防止 §2.2 的"一笔画主导策略"）；
   - 至少 2 对端点不在同一行/列（避免过度对称）。
5. **60 关在运行时用写死的固定种子生成**，种子形如 `'powerlink|v1|L07|5x3|low'`（关卡 id + 尺寸 + K + σ）。由于 PRNG 全程为 32 位整数运算，**任何设备、任何时间生成的 L07 都是同一张图** —— player-facing 效果等同于静态固化，但省掉了几十 KB 的坐标数据。
6. **每日挑战**用同一算法 + 日期种子 `'powerlink|daily|YYYY-MM-DD'` 生成（详见 ux-save-spec.md §6）。

> **关于 backbite**：这是比 2-opt 更合适的选择 —— 它是**保哈密顿性**的局部变换（随机挑一个端点，连向它的一个网格邻居，再删掉对侧那条路径边，结果仍是一条哈密顿路径），因此**永不失败、无回溯爆炸、无需重试循环**。设计组原先建议的 2-opt 由工程改为 backbite，此处从实现。

> **确定性红线**：生成器内**严禁调用 `Math.random()`**，全部随机数必须来自种子驱动的 `mulberry32`。所有算术需为 32 位整数运算（`Math.imul` + 无符号位移），以保证跨 JS 引擎位级一致。建议保留一个自检：同一种子连跑 100 次，输出 JSON 完全相同。

### 7.3 提示系统（Hint）

- 点击「提示」→ 高亮**一条**尚未正确铺设的路径的**完整正确走法 1.5 秒**（来自预存的参考解）。
- 无次数限制、无冷却、无货币。但**本次使用提示后，该关本次结算最高 2★**（重玩不使用提示可拿回 3★）。
- 理由：保护 P2 的成就感，同时不惩罚卡关玩家（符合 SDT 自主）。
- 数据依赖：每个静态关卡需附带参考解 `solution`（每对颜色的完整格子序列）。每日挑战因构造式生成，天然持有参考解。

### 9.1 可翻转的产品常量面板

全部集中在 `levels.js` 顶部的 `POWERLINK_CONFIG`，改一行即生效、不需动逻辑代码。产品侧调参**只应改这里**：

| 常量 | 当前值 | 翻转后的效果 |
|---|---|---|
| `ALL_PACKS_OPEN` | `false` | 改 `true` → 忽略所有星数门槛，60 关全开（用户若反馈"卡关烦"可一键切换） |
| `PACK_UNLOCK` | `{p1:0, p2:22, p3:50, p4:80}` | 调高/调低解锁节奏 |

| `STAR2_COVER_PERCENT` | `80` | 2★ 覆盖率门槛 |
| `STAR3_REQUIRE_FULL` | `true` | 改 `false` → 3★ 不再要求满铺（**不建议**，会瓦解 §1-P2 的推理动机） |
| `MOVES_AFFECT_STARS` | `false` | 改 `true` → 步数计入星级（**不建议**，见下方红线） |
| `HINT_PENALTY_MAX_STAR` | `2` | 改 `3` → 用提示也能拿满星；改 `1` → 惩罚更重 |
| `DAILY_ALLOW_MAKEUP` | `false` | 改 `true` → 允许补做往日题（会削弱每日仪式感、可被刷连胜） |
| `DAILY_HISTORY_DAYS` | `7` | 战绩回看天数 |
| `SOUND_DEFAULT_ON` | `true` | 新档案默认音效开关 |

> **设计红线提醒**：`MOVES_AFFECT_STARS` 与 `STAR3_REQUIRE_FULL` 这两个开关会**直接动摇设计支柱**。前者会催生"背最优解"的主导策略并把休闲玩家挡在满星之外（违背 P3）；后者会让 3★ 失去"满铺"这一清晰、可视、可行动的目标（违背 P2）。如需翻转请回 §1 复核。

## 10. 给工程组的关键假设（需程基岩确认）

1. 棋盘用 **单个 `<canvas>`** 渲染（非 DOM 格子），配合 `devicePixelRatio` 缩放；UI 层用 DOM。理由：拖拽 60fps + 发光效果 DOM 扛不住。
2. 输入统一用 **Pointer Events**（`pointerdown/move/up/cancel`）覆盖鼠标/触屏/触控笔，棋盘容器设 `touch-action: none`。
3. **`file://` 下 `localStorage` 可能不可用**（部分浏览器把 file 视为不透明源）。必须做 try/catch 降级到内存存储，并在界面顶部显示一条"当前环境无法保存进度"的提示条。
4. 所有资源内联：CSS 内联或同目录 `.css`，图标用**内联 SVG**，音效用 **WebAudio 合成**，字体用系统字体栈。**零 CDN、零 fetch**。
5. 关卡数据 `levels.js` 由设计组提供参数表，实际 60 关数据请工程用 §7.2 算法离线跑一次并固化；设计组负责抽验难度手感。
6. 严禁触碰仓库根目录的 `index.html` / `daily-report.json` / `build-report.mjs` / `.github/`。所有文件仅在 `game/` 下新增。
7. 需要在 `game/` 或仓库根同级确认 `.nojekyll` 的处理（由主理人统筹，设计组仅提示：文件名不要以 `_` 开头，避免 Jekyll 忽略）。
