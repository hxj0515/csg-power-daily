# 电亮全城 · PowerLink

电力主题的 Flow-Free 式连线解谜小游戏。把发电站接到用电点，铺满全城不断电。

> 纯静态 · 无构建步骤 · 无第三方依赖 · 无 CDN · 无联网行为 · 离线可玩

---

## 玩法

1. **按住**任意一个发电站端点，**拖动**画出电缆，**松手**结束。
2. 同色两端接通即完成一条线路。线缆不能交叉：拖进别人的线时，那条线会**从被撞的那一格起截断到尾部**（标准 Flow Free 行为）；拖回自己线的中段则截断到该点。
3. **胜利条件**：所有颜色对全部接通。没有失败态，没有倒计时，没有生命值。
4. **星级**
   | 星级 | 条件 |
   |---|---|
   | ★ | 所有配对接通 |
   | ★★ | 接通且覆盖率 ≥ 80% |
   | ★★★ | 接通且 **100% 铺满全盘** |

   每一关都保证存在 100% 满铺解（关卡由"先造解、再挖题"的构造式算法生成）。

   > **星级用整数计数**：先判定"是否全部接通"，再按"已铺格数 / 总格数"的整数比较判定——满铺 = 3★；已铺格数 × 100 ≥ 总格数 × 80 = 2★；否则 1★。**覆盖率判定不使用浮点除法**，从数学上杜绝 `0.8` 之类浮点误差导致错判。步数不计入星级，仅作最佳记录展示。

### 内容

- **闯关模式**：60 关，分 4 个关卡包（5×5 → 9×9），端点对数 3 → 7 递进，难度单调递增。每包 15 关，网格在升档处与每 ~4–5 关插入一道"缓冲关"。
  - **关卡包按累计星数松门槛解锁**：第 1 包全开；第 2 包需累计 **22★**；第 3 包需 **50★**；第 4 包需 **80★**（满星 180）。门槛为"松"——只需历史累计星数达到即可，与具体在哪关拿星无关。`ALL_PACKS_OPEN` 总开关可一键全部开放。
- **每日挑战**：用**设备本地日期** `YYYY-MM-DD` 作为随机种子确定性生成，**全员同题**。附最近 7 天记录与连续天数统计。**不允许补做往日**：只生成当天关卡，过去的格子灰显、不可点击（没有"补做"入口）。
- **提示**：闪现一条未完成线路的前半段正确走法。使用后本局结算**星级上限锁定为 2★**（`HINT_PENALTY_MAX_STAR=2`，重玩不使用提示即可拿回 3★）。

### 可访问性

- 每对线路除颜色外还有**形状标记**（圆 / 方 / 三角 / 菱形 / 六边 / 星 / 十字 / 环），色觉异常玩家可辨。
- 单关颜色数上限 7，避免认知过载。
- 支持键盘完整操作；棋盘 canvas 有 `aria-label` 说明。
- 尊重系统 `prefers-reduced-motion`，另有独立的「减少动效」开关。
- 触控目标 ≥ 44px。

## 本地运行

**方式一（最简单）**：直接双击 `index.html`，用浏览器打开即可。

游戏刻意**不使用** `<script type="module">`，因此在 `file://` 协议下可以直接运行，不需要任何服务器。

**方式二（推荐用于完整体验存档）**：起一个本地静态服务器，例如在本目录执行

```bash
python -m http.server 8000
# 然后访问 http://localhost:8000/
```

或

```bash
npx serve .
```

> **关于 `file://` 下的存档（已做扎实的降级）**：部分浏览器把 `file://` 视为不透明源，`localStorage` 会被禁用。游戏对此做了容错——启动时**实测一次** `setItem + getItem + removeItem`（仅凭 `typeof localStorage` 不可靠：file://、隐私模式、关闭 Cookie 下对象存在却一写就抛）。一旦探测失败：
> - 自动降级为**内存存储**，当前会话照常游玩、建档、通关；
> - 页面顶部常驻一条**黄色警告条**，说明存档无法保留；
> - 警告条内「**立即导出**」按钮被高亮（琥珀色脉冲动画），引导用户随时把内存中的进度导出为 JSON 备份；
> - 即便 localStorage 在游玩中途**突然失效**（运行时写失败），也会触发同样的降级与提示（顶部警告条 + 高亮导出），不会静默丢数据。
>
> 注意：内存态在刷新后会丢失，这是 file:// 环境下不可避免的——放到 `http://` 或 `https://` 下即可正常持久化存档。导出 JSON 是降级下的唯一备份手段。

## 可翻转的产品常量（决策面板）

所有"产品拍板"的参数都集中在 `levels.js` 顶部的 **`var POWERLINK_CONFIG`**（即运行时全局 `window.POWERLINK_CONFIG`），以及 `game.js` 内的 `DEFAULT_CFG` 兜底。改一处即可改全局行为，**无需动逻辑代码**：

| 常量 | 出厂值 | 含义 |
|---|---|---|
| `LEVELS_PER_PACK` | `15` | 每包关数（共 4 包 → 60 关）。改包数需同步 `PACKS` 与 `PACK_UNLOCK` 键。 |
| `ALL_PACKS_OPEN` | `false` | 总开关。`true` 时所有关卡包直接全开，跳过累计星数门槛。 |
| `PACK_UNLOCK` | `{p1:0, p2:22, p3:50, p4:80}` | 各包解锁所需的**累计星数**（松门槛）。第 1 包恒为 0。 |
| `STAR3_REQUIRE_FULL` | `true` | 3★ 是否必须 100% 满铺（否则允许靠覆盖率达标）。 |
| `STAR2_COVER_PERCENT` | `80` | 2★ 的覆盖率门槛（整数百分比，非浮点）。 |
| `MOVES_AFFECT_STARS` | `false` | 步数是否影响星级（当前关闭：星级只看接通 + 覆盖率）。 |
| `HINT_PENALTY_MAX_STAR` | `2` | 使用提示后本关星级上限。 |
| `DAILY_ALLOW_MAKEUP` | `false` | 是否允许补做往日每日挑战（`false` = 只生成当天，过去灰显）。 |
| `DAILY_HISTORY_DAYS` | `7` | 每日挑战历史展示天数。 |
| `SOUND_DEFAULT_ON` | `true` | 音效默认开关（WebAudio 实时合成，零音频文件）。 |

> 这些常量同时被 `levels.js`（关卡 / 包 / 每日挑战）与 `game.js`（星级评定、包解锁、提示封顶、降级、音效）读取，`game.js` 以 `window.POWERLINK_CONFIG || DEFAULT_CFG` 合并，缺字段自动兜底，不会因漏配而崩溃。

**拍板落地的 6 项决策**对应上表：

1. 关卡数 60 = 4 包 × 15，网格 5×5→9×9，难度递增；包解锁用 `PACK_UNLOCK` 松门槛（22/50/80★），`ALL_PACKS_OPEN` 一键全开。
2. 提示封顶 2★：`HINT_PENALTY_MAX_STAR=2`，重玩不使用提示仍可 3★。
3. 音效 = WebAudio 振荡器实时合成（连线/通关/错误等），零音频文件；`SOUND_DEFAULT_ON` 默认开，设置可关。
4. 每日挑战用设备本地日期 `YYYY-MM-DD` 种子，`DAILY_ALLOW_MAKEUP=false` → 不补做往日。
5. file:// 下降级：`LS` 模块实测探测 + 运行时降级，内存存储 + 顶部警告条 + 高亮导出按钮（见上节）。
6. 星级整数计数（不用浮点比较覆盖率）；步数不计入星级。

## 关卡是怎么来的

采用**"先造解、再挖题"**的构造式生成，而不是随机布点后求解——这样能从数学上保证每关都有 100% 满铺解：

1. 在 N×N 网格上铺一条**蛇形哈密顿路径**（经过每格恰好一次，任意 N 都必然存在）。
2. 用 **backbite** 局部变换反复随机扰动这条路径。backbite 每一步都保持哈密顿性，因此永不失败、没有回溯爆炸的风险。
3. 按目标端点对数 K 和方差档位，把路径**切成 K 段连续子路径**。
4. 每段的首尾格就是一对同色端点，整段就是该对的参考解 —— 所有段拼起来恰好覆盖全盘。
5. 合法性过滤：段长 ≥ 3；一对端点不得正交相邻；单段长度 ≤ 总格数 55%（防止"一笔画填满"的主导策略）；至少 2 对端点不同行不同列。不满足就再扰动重切，最多 220 次，并有两级降级兜底。

随机源是 `mulberry32 + FNV-1a 字符串哈希`，全部为 32 位整数运算（`Math.imul` + 无符号位移），**在任何 JS 引擎上位级一致**。因此：

- 60 个内置关卡在运行时用写死的种子生成，任何设备、任何时间打开都是同一批图，等价于固化数据；
- 每日挑战用 `powerlink|daily|YYYY-MM-DD` 作种子，全员同题。

## 存档格式

存在 `localStorage`：

| 键 | 内容 |
|---|---|
| `powerlink:profiles:v1` | 档案数组（JSON） |
| `powerlink:current:v1` | 当前档案 id |

单个档案结构：

```json
{
  "id": "p_xxxx",
  "name": "小李",
  "color": "#38e1ff",
  "icon": "circle",
  "createdAt": 1754800000000,
  "updatedAt": 1754800000000,
  "levels": { "L01": { "stars": 3, "bestMoves": 5, "completed": true } },
  "daily":  { "2026-08-10": { "stars": 2, "completed": true } },
  "settings": { "sound": true, "reduceMotion": false }
}
```

- 最多 6 个档案；支持创建 / 切换 / 编辑（改名 + 换头像）/ 删除。
- 星级**只增不减**，最佳步数只降不升；步数不影响星级。
- **导出**：单档案或全部档案导出为 JSON 文件下载；同时提供文本框可直接复制（应对 `file://` 下下载被拦截的情况）。
- **导入**：选择文件或粘贴 JSON。合并规则为**同 id 覆盖、新 id 追加**；全程 `try/catch`，字段逐项规范化（越界星级夹取、非法日期键丢弃、非法颜色/图标回退默认），脏数据不会污染存档也不会让页面崩溃。
- 通关、切换档案、改设置时自动保存。

## 浏览器要求

现代浏览器（Chrome / Edge / Firefox / Safari，含移动端）。使用了 Canvas 2D、Pointer Events（不支持时自动回退到 mouse + touch 事件）、`localStorage`（不可用时回退到内存）、WebAudio（不可用时静音）。所有可选能力均有降级处理，不会出现控制台报错。
