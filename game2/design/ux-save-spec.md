# UX 与多档案存档规格（game2 / PowerLink2）

## 1. 屏幕流程图

```
启动 App
  ├─ 首次（无档案）→ 建档引导（输入名 / 选色 / 选图标）
  └─ 已有档案 → 档案选择（列表 + 新建 / 导入 / 设置）
        │
        ├─ 主菜单（档案卡 + 章节入口 + 每日挑战 + 设置）
        │
        ├─ 章节选择 → 关卡选择 → 答题流程
        │      答题：题干 → 作答 → 提交 → 知识点卡片（讲解）→ 下一题
        │      └─ 关卡结算（星级 / 得分 / 错题回顾）→ 返回关卡选择
        │
        ├─ 每日挑战（独立入口，任意时间可玩，按本地日期记录）
        │
        └─ 设置（音效 / 减少动效 / 导出 / 导入 / 改档 / 删除档）
```

关键决策点：
- 无档案必须建档才能进入主菜单。
- 章节/关卡入口显示锁定态（未达星数门槛）。
- 答题中可暂停（Esc）→ 暂停弹窗（继续 / 重开 / 退出到关卡）。

## 2. 交互模型
- **鼠标**：点击选项；排序题支持拖拽，或上/下按钮（拖拽不可用时回退）；连线题点左项再点右项完成配对。
- **键盘**：数字键 1–9 / 字母 A–Z 选选项；Enter 提交/继续；Esc 暂停；Tab/Shift+Tab 在可交互元素间移动（焦点环可见）；方向键在选项间移动。
- **触控**：与鼠标等价；拖拽排序在触屏用「长按+拖动」或上下按钮。
- 所有可点元素命中区 ≥ 44×44px（可访问性）。

## 3. 多档案存档规格
- localStorage 键：
  - `powerlink2:profiles:v1` → JSON 数组，所有档案。
  - `powerlink2:current:v1` → 当前档案 id（字符串）。
- 单个档案结构（严格按此）：

```js
{
  id: string,            // 唯一，建议 Date.now() + 随机后缀
  name: string,          // 展示名，可重名
  color: string,         // 主题色 hex，从限定调色板选
  icon: string,          // emoji 或图标 token（见 art-direction）
  createdAt: number,     // 时间戳
  updatedAt: number,     // 时间戳
  progress: {            // 关卡进度，key = levelId
    [levelId]: { stars: number /*0-3*/, bestScore: number, completed: boolean, wrong: number }
  },
  daily: {               // 每日挑战，key = 本地日期 YYYY-MM-DD
    [dateStr]: { stars: number, completed: boolean }
  },
  settings: { sound: boolean, reduceMotion: boolean }
}
```

- `wrong` 定义：该关卡累计答错次数（用于薄弱点统计）。

## 4. 导出 / 导入 JSON
- 导出格式：`{ version: 2, exportedAt: ISOString, profiles: [ /* 完整档案数组 */ ] }`
- 导入规则：
  - 解析失败 → try/catch 捕获，提示「文件损坏」并中止。
  - `version ≠ 2` → 拒绝导入并提示版本不符。
  - 按 `id` 合并：同 id 以**导入覆盖**现有；新 id 追加；**不删除**现有未匹配档案。
  - 单条档案字段缺失 → 用默认值兜底（见 §7），不整体失败。

## 5. 自动保存时机
- 关卡完成（写 `progress[levelId]`）后立即保存。
- 每日挑战完成（写 `daily[dateStr]`）后立即保存。
- 设置变更（`settings`）立即保存。
- 档案新建 / 改名 / 改色 / 改图标 / 删除 / 切换当前档：操作后立即保存两个键。
- 不需要在单题内实时写盘（progress 仅在关卡结算落库），减少写入频率。

## 6. 可访问性（不止颜色）
- 题型反馈不仅靠颜色：正确 = ✅ + 「正确」文字，错误 = ❌ + 「错误」文字 + 知识点卡片。
- 选项带字母/数字标签（A/B/C 与 1/2/3）便于口述与键盘操作。
- 焦点环高对比可见；`reduceMotion` 关闭所有过渡动画。
- 文字与背景对比度 ≥ 4.5:1；排序/连线提供非拖拽替代（按钮 / 点击选择）。

## 7. file:// 下降级方案
- 启动时探测 localStorage：try { 测试 set/get/remove } catch → 判定不可用。
- 不可用 → 切换为**内存存储**（进程内 JS 对象）+ 顶部黄色提示条：「本地存档不可用，进度仅本次有效，请及时导出备份」+ 高亮「导出」按钮。
- 即便 memory 模式，导出功能仍可用（导出当前内存档案），导入仍可加载到内存。
- 注意：file:// 的 origin 为 `null`，不同 file:// 页面可能共享 localStorage，且部分浏览器（旧 Safari）完全禁用 → 必须按上法兜底。

## 8. 边缘情况（15 条）
1. localStorage 完全不可用（file:// / 隐私模式 / 禁用）→ 内存存储 + 提示条（见 §7）。
2. 读取 profiles 为损坏 JSON → 解析失败重置为空数组，提示「存档已重置」。
3. `current` id 指向不存在的档案 → 回退到首个档案；无档案则引导建档。
4. 允许重名档案 → id 仍唯一（时间戳 + 随机），不阻止重名。
5. 导出 JSON 被手动改坏 → 导入 try/catch 跳过，提示具体错误。
6. 导入 id 与现有冲突 → 按 id 合并（导入覆盖同 id，新增追加）。
7. 导入 `version ≠ 2` → 拒绝并提示版本不符。
8. 删除唯一档案 → 强制建档引导，禁止空档案进入主菜单。
9. 删除当前档案 → 切换至其余首个；无其余则建档。
10. 写入触发 `QuotaExceededError` → 捕获并提示「存储空间已满，请清理或导出」。
11. `progress` 中 levelId 在题库更新后不存在 → 忽略该条目，不报错。
12. daily 日期跨天/时区 → 统一用本地日期函数 `YYYY-MM-DD`（基于用户时区）。
13. 多标签页同写冲突 → 监听 `storage` 事件刷新当前档案（可选增强）。
14. 旧档案缺 `settings` 字段 → `sound`/`reduceMotion` 默认值兜底（true / false）。
15. 档案数过多（>50）→ 列表滚动 + 性能提示，避免一次渲染卡顿。
